# weber

Docker-образ для публикации статического контента (например, сгенерированной документации dbt) из S3-хранилища через nginx.

Содержимое ZIP-архива скачивается из S3, распаковывается в новую директорию, после чего атомарно подменяется символическая ссылка `/tmp/www`. nginx раздаёт этот каталог, а фоновый процесс периодически обновляет контент без остановки сервиса.

## Как это работает

1. `entrypoint.sh` проверяет `UPDATE_INTERVAL_MINUTES`, создаёт временные каталоги nginx, генерирует `/tmp/nginx/nginx.conf` из шаблона и запускает первое обновление.
2. `update.sh` подписывает S3-запрос (AWS Signature V2, HMAC-SHA1), скачивает архив `S3_WWW_ZIP`, распаковывает его в `/tmp/www-<время>/<SERVICE_PATH>`, меняет символическую ссылку `/tmp/www` и удаляет старую версию. В каталог контента пишется `last_update.txt` с таймкодом обновления.
3. В фоне с интервалом `UPDATE_INTERVAL_MINUTES` обновление повторяется. При ошибке в лог пишется сообщение, но nginx продолжает работать.
4. nginx запускается в foreground с конфигом `/tmp/nginx/nginx.conf`; включены `index index.html` и `autoindex on`.

## Сборка

```sh
./build.sh
```

Эквивалент: `docker build . -t weber --no-cache`.

Базовый образ можно переопределить:

```sh
docker build . -t weber --no-cache --build-arg BASE_IMAGE=<another-image>
```

## Запуск

Готовый пример со всеми параметрами — в `run.sh`:

```sh
./run.sh
```

Минимальный запуск:

```sh
docker run -d --name weber \
  -e S3_PROTOCOL=http \
  -e S3_HOST=s3.example.local \
  -e S3_PORT=8888 \
  -e S3_BUCKET=docs \
  -e S3_WWW_ZIP=dbt_docs.zip \
  -e S3_ACCESS_KEY=... \
  -e S3_SECRET_KEY=... \
  -e SERVICE_PATH=/dbt_docs/ift \
  -e SERVICE_PORT=81 \
  -e UPDATE_INTERVAL_MINUTES=5 \
  -e NGINX_ACCESS_LOG=/dev/stdout \
  -p 8080:81 \
  -u 11111 \
  weber
```

После запуска документация доступна на `http://localhost:8080/dbt_docs/ift/`.

## Переменные окружения

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `S3_PROTOCOL` | `https` | Протокол подключения к S3 (`http` / `https`). |
| `S3_HOST` | — | Хост S3. Обязательна. |
| `S3_PORT` | `443` | Порт S3. |
| `S3_BUCKET` | — | Имя бакета. Обязательна. |
| `S3_WWW_ZIP` | — | Имя ZIP-объекта в бакете. Обязательна. |
| `S3_ACCESS_KEY` | — | Ключ доступа S3. Обязательна. |
| `S3_SECRET_KEY` | — | Секретный ключ S3. Обязательна. |
| `S3_CONNECT_TIMEOUT` | `10` | Таймаут подключения к S3, сек. |
| `S3_MAX_TIME` | `300` | Максимальное время S3-запроса, сек. |
| `SERVICE_PORT` | `8080` | Порт, на котором слушает nginx. |
| `SERVICE_PATH` | пусто | Путь внутри web-рута, куда распаковывается архив; он же префикс URL. |
| `UPDATE_INTERVAL_MINUTES` | `60` | Интервал обновления контента, минуты (целое число > 0). |
| `UPDATE_VERSION` | пусто | Суффикс имени скрипта обновления: `/app/update${UPDATE_VERSION}.sh`. Скрипт должен присутствовать в образе или быть смонтирован. |
| `NGINX_ACCESS_LOG` | `off` | Директива `access_log` (например, `/dev/stdout`). |
| `NGINX_ERROR_LOG` | `/dev/stdout warn` | Директива `error_log`. |
| `DEBUG` | пусто | Любое непустое значение: печатать конфиг nginx и все переменные окружения. |
| `TZ` | — | Часовой пояс (используется в логах и подписи S3-запросов). |

## Структура

- `Dockerfile` — образ на базе Astra Linux UBI18 с nginx, curl, unzip и ca-certificates.
- `build.sh` — сборка образа `weber`.
- `run.sh` — пример запуска контейнера.
- `app/entrypoint.sh` — точка входа: генерация конфига, первое обновление, планировщик, запуск nginx.
- `app/nginx.conf.template` — шаблон конфига nginx (`envsubst` подставляет `SERVICE_PORT`, `NGINX_ERROR_LOG`, `NGINX_ACCESS_LOG`).
- `app/update.sh` — скачивание и атомарная подмена контента из S3.
- `app/*.bak` — архивные версии скрипта обновления (в образ не попадают).

## Примечания

- Контейнер рассчитан на запуск от непривилегированного пользователя (в примере `-u 11111`): pid, логи и временные файлы nginx находятся в `/tmp`.
- Архив должен содержать содержимое сайта в корне (например, `index.html`).
- `DEBUG=1` выводит в логи **все** переменные окружения, включая S3-ключи. Используйте только для отладки.
- `curl -k` отключает проверку TLS-сертификата S3; для продакшена используйте доверенный сертификат.
